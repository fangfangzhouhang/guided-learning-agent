# 升级技术路线与分工建议 v1

> 当前状态：V0.1 已交付（规则状态机 + 选择题题库 + SQLite + 网页/手机演示版）。
> 本文档回答三个问题：升级需要什么、按什么路线升、团队怎么分工学什么。

## 一、升级前需要准备的东西（按重要性）

| # | 需要什么 | 为什么 | 谁提供 |
|---|---|---|---|
| 1 | 老师的 PPT（几份） | 题库扩充的唯一权威来源；校准 rbb′（200/300Ω）、UBE 等口径 | ark 发给 Muse |
| 2 | 一个大模型 API Key（DeepSeek 即可，很便宜） | V0.3 自由问答判读与引导生成要用；没有它只能做选择题 | 团队注册，费用可问老师报销 |
| 3 | 部署决定：给谁用、在哪跑 | 只给组内演示 → 现状够用；给全班试用 → 需要一台云服务器（学生机即可） | 团队和老师确认 |
| 4 | 3–5 名真实试用同学 | 没有真实作答数据，教学策略优化就是闭门造车 | 团队招募 |
| 5 | 组员名单 + 各自基础（谁会 Python/前端/模电最好） | 分工要落到具体人，而不是只分到组 | 组长统计 |
| 6 | 老师的验收时间点 | 决定路线只走到哪一版，不贪多 | ark 确认 |

**明确不需要**：不需要训练模型、不需要 GPU、不需要大数据集。
自由回答的判读用现成大模型 API 就够；微调是积累了真实作答数据之后（V1.0 以后）才考虑的事，现在提训练为时过早。

## 二、技术路线（五级台阶，每级都有验收标准）

### V0.1 ✅ 已完成：能跑的闭环
规则状态机（诊断→提示/示范→练习→独立测验）、6 个知识点、误区编码、SQLite 记录。

### V0.2 内容扩充版：把课讲全
- PPT 解析入库：`python-pptx` 提取 PPT 文字/公式要点 → 按 `content/*.json` 格式结构化
- 每知识点题目 3 道 → 8–10 道，新增**填空式计算题**（数值容差判分，不只选择题）
- 补齐知识图谱 U7 多级放大、U8 频率响应入门；按 PPT 校准公式口径
- 验收：8 个知识点全部能走完闭环；题目答案经组内交叉核对无争议

### V0.3 真 Agent 版：从"选题"到"对话"
- 接入 LLM：学生可以**打字提问、打字作答**；LLM 在状态机约束下做三件事——
  判断作答对错、归因到误区编码、按当前阶段生成引导话术（规则兜底，判读结果必须落回已有误区编码，落不回就转人工预设分支）
- RAG：把 PPT+教材切片做 embedding 向量检索，回答必须带来源出处，查不到就明说
  （轻量实现：FAISS 或 sqlite-vec，不上独立向量数据库）
- 流式输出、对话上下文管理
- 验收：20 个标准教学案例（预设学生回答）全部走对分支；自由提问不编造公式

### V0.4 学习者模型版：记得住每个学生
- 误区历史画像：每个学生反复错的误区自动置顶复习
- 间隔复习：按遗忘曲线简化调度（先用固定间隔+对错调整，FSRS 算法作选学）
- 学习报告页（学生看自己）+ 教师看板（全班误区分布统计）
- 数据库 SQLite → PostgreSQL（多人同时用才需要）
- 验收：一个学生隔天回来，系统能主动推他昨天错的误区变式题

### V1.0 部署验证版：拿数据说话
- Docker 打包部署到云服务器，简单账号系统，手机/电脑都能访问
- 小范围对照试用：用独立测验成绩对比"用系统学"与"只看 PPT 学"的差异
- GitHub Actions 自动测试，PR 必须过测试才能合并
- 验收：≥10 名同学完整用过，留下一份试用数据小结

> LangGraph、多 Agent 框架放在 V0.3 之后按需引入，不提前学、不提前上。

## 三、团队要学什么（分层，别全员学所有）

**全员必学（1 周内）**：Git/GitHub 协作（分支、PR、Issue）、JSON 数据格式、HTTP 与 API 的基本概念、Python 基础语法。

**按组学**：
- A 组：Python 进阶（函数/类/异常）、状态机设计、Prompt 工程、大模型 API 调用
- B 组：模拟电子技术本身（这组模电必须最强）、python-pptx、文档结构化、embedding 与检索的基本概念（V0.3）
- C 组：HTML/CSS/JavaScript、FastAPI、Docker 基础、移动端适配

**选学/前沿（有余力再碰）**：LangGraph、FSRS 算法、Langfuse 评测追踪。

## 四、建议分工（三组，沿用仓库现有边界）

按 7–9 人编制；人数少时按文末压缩法合并。

| 组 | 人数 | 负责 | 仓库边界 | 交付物 |
|---|---|---|---|---|
| A 智能教学组 | 2–3 | 教学决策、提示策略、LLM 判读、评测案例集 | `app/tutor.py`、`app/llm.py`、`tests/` | 状态机升级、20 个标准案例全过 |
| B 知识资源组 | 2–3 | PPT 解析、题库扩充、误区库、RAG 语料 | `content/`、`app/knowledge.py`、`docs/` | 每知识点 8–10 题、来源可查 |
| C 产品工程组 | 2–3 | 前端（移动端优先）、部署、数据库、教师看板 | `app/main.py`、`app/storage.py`、`static/` | 手机上好用的界面、可部署的版本 |
| 集成负责人 | 1（建议 ark） | 接口契约、PR 审核、版本验收、和老师对接 | `contracts/`、全仓 | 每版验收签字 |

规则只有一条：**每块代码只有一个负责组**，跨组改动走 PR 并请对方组 review；
接口（`contracts/api.md`）改动必须负责人批准。

**人数压缩法**：4–5 人时 A+B 合并为"教学与内容组"（3 人），C 组 2 人；
3 人时一人一组，负责人由 A 组兼任。分工再少也不能省掉 B 的题目核对，
错题库比错代码更伤这个产品。
