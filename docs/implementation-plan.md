# 落地计划：把调研借用清单变成代码

> 来源：2026-11-07 技术调研 Top 5（报告存项目研究记录）。
> 原则：每批做完必须过 harness（`python -m evals.run_evals` + pytest 全绿）
> 才算完成；数字不升不算改进。LangGraph 迁移不在本计划内——那是团队
> 学完阶段一、二后亲手做的事。

## 批 1 · V0.3.3 判分与提示词加固（纯方法，无新依赖）

1. 开放题判分改结构化 rubric 提示（借 Prometheus 模板的“形”，不用其模型）：
   评分标准逐项列出、逐项核对、先判定因果链方向对不对，再数要点；
   明确写死“只有关键词没有因果 = 不通过；字数多不加分”
2. 判分自洽投票：同一答案独立判 N 次（默认 3，`JUDGE_SAMPLES` 可调），
   多数决；全部调用失败才回落到关键词判分
3. 「问老师」系统提示按 LearnLM 五原则（主动学习/认知负荷/适应性/好奇心/
   元认知）+ Khanmigo 复盘规则重写：**未尝试前只给提示；已尝试且答错后
   必须直白讲清错在哪、正确链条是什么**，不许无限绕圈
- 验收：pytest 全绿（含投票逻辑单测）；harness A 7/7 不回退；
  LLM 判分一致率在配 key 的机器上用金标集补测并记录（目标 > 离线基线 0.58）

## 批 2 · V0.35 Elo 双评级 + 干扰项起草工具

1. Elo 双评级（约 30 行，storage 新增 ratings 表）：每次作答同时更新
   学生分与题目分（题目 K 值更小）；画像页展示题目难度（数据标定值），
   内容生产时优先复测高难+高误区题
2. 干扰项起草工具 `tools/draft_items.py`：输入知识点与误区码 → LLM 起草
   整题（题干+正确项+按误区码的干扰项+解析）→ 输出到 `drafts/` 待审区，
   **永不直接写 content/**；人工双审后手工入库（流程写进 CONTRIBUTING）
- 验收：Elo 更新有单测（赢难題涨分多、输易题掉分多）；起草工具能对
  任一现有误区码产出一份结构合法的待审草稿（JSON 过课程包校验函数）

## 批 3 · V0.4 FSRS 复习系统

1. 接入 py-fsrs（MIT，锁版本，只用默认参数）：每个（学生，知识点）一张卡，
  完成一轮学习后按结果映射评级——干净通过 Easy / 有错通过 Good /
  靠提示通过 Hard / 未通过 Again
2. 新增「复习」页与到期队列 API：到期未复测的知识点按 FSRS 排期出现；
  复测走现有学习流程，测验结果回写评级
3. 参数优化器（optimizer）**不启用**：等全队复习记录累计数百条再议，
  并在 docs 里写明启用条件
- 验收：评级映射与到期计算有单测；harness 新增案例（到期知识点必须
  出现在复习队列里）并全过

## 明确不做（及原因）

- 神经知识追踪 / 本地判分模型：数据与算力都不够（调研结论）
- m3e 向量模型：许可证冲突；RAG 选型已定 bge-small-zh-v1.5 + sqlite-vec
- 任何逐字导入的外部题库：许可证不兼容（扩张调研结论）
