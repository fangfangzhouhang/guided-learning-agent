# V0.5 RAG：带出处的问答

让「问老师」从“凭模型印象答”变成“先查课程资料、带出处答、查不到就
明说”。检索只覆盖本项目的课程包（知识点概述、误区库、题目与解析）——
范围小而准，正是这个场景需要的。

## 组件（2026-11-07 选型，约束变更后）

原调研在“普通笔记本能跑”的约束下选的是 bge-small-zh + sqlite-vec。
项目负责人确认该约束取消（有显卡可用、功能优先）后升级为：

| 环节 | 选型 | 说明 |
|---|---|---|
| 向量模型 | BAAI **bge-large-zh-v1.5**（MIT，1024 维） | 中文检索质量明显强于 small；查询侧按官方建议加指令前缀 |
| 关键词召回 | 自实现 Okapi **BM25**（字符双字组 + ASCII 词元） | 补向量的短板：公式符号（`Rc//RL`、`UCEQ`）和精确术语；两路用 RRF 融合 |
| 重排模型 | BAAI **bge-reranker-large**（MIT） | 融合候选 top-20 后逐对精排，取 top-5 |
| 向量存储 | **sqlite-vec**（锁版本意识同前） | 复用 SQLite，不引入新服务 |
| 生成 | 现有 DeepSeek 教师对话 | 系统提示注入证据并强制标注出处编号 |

追问会先做查询改写：问题很短或带指代词（它/这/那）时，把上一条学生
问题拼到检索词前面——“那它对输出电阻有影响吗？”单独检索没有可搜的
词，拼上前文才找得到证据。改写只影响检索，不改变对话本身。

模型文件在 `models/`（`python -m tools.build_rag` 自动下载），索引在
`rag.db`，两者都是构建产物、已 gitignore、永不进仓库。

## 拒答策略

重排分数经 sigmoid 归一后低于阈值（默认 0.35，环境变量
`RAG_MIN_SCORE` 可调）的证据一律丢弃；一条不剩时视为“没查到”：
系统提示要求老师明确说课程资料里没查到、不许编造公式与数值。
阈值是用 `evals/rag_cases.json`（含 2 条离题问题）校准的，不是拍的。

## 实测（2026-11-07，本机 CPU，真实模型）

- 索引：57 条语料块（7 个知识点 × 概述/误区库/题目解析）
- 检索评测（`evals/rag_cases.json`）：纯向量版 8 条 **8/8**；混合检索
  （BM25+向量 RRF）后评测扩到 11 条（含 rbe 公式、UCEQ、Ro/Ri 三条
  符号/公式型问题，向量的传统弱项）复测 **11/11**
  - 课程问题：期望知识点全部进入证据集前 3
  - 2 条离题问题（红烧肉、静夜思）：全部正确返回“无证据”，走拒答路径
- 分数分离度：课程问题的榜首证据概率 ≈ 0.99，离题问题的最高分 ≈ 0.00，
  阈值 0.35 位于两团分布的空档里，不是贴边过的
- 踩坑记录：第一版对 CrossEncoder 的输出又套了一层 sigmoid（它默认
  已输出概率），导致相关证据被压到 0.73、离题证据浮在 0.50，评测
  5/8；定位后去掉双重 sigmoid 并把评测口径改为“期望知识点进前 3”
  （RAG 喂给老师的是证据集，只看榜首过严），复测 8/8

## 怎么建/怎么测

```bash
pip install -r requirements.txt   # 含 sentence-transformers、sqlite-vec
python -m tools.build_rag --check # 下载模型 + 建索引 + 跑检索评测集
python -m pytest -q               # 单测用替身向量，不下模型、不联网
```

有 GPU 的机器上把环境变量 `RAG_DEVICE=cuda` 设上即走显卡；
不设时自动探测。
