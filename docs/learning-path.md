# 团队学习路径：怎样才算"会搭建 Agent"

> 目标已定版：不是组内演示，而是做一个能公开发布到 GitHub 的开源级强学习 Agent。
> 按这个目标要求全员：**必须真正学会搭建 Agent，而不是只会用现成平台。**
> 学习全部围绕本仓库进行——每学一个概念，都在本项目里有对应的代码和练手任务。

## 结论先行：学什么、不学什么

| 内容 | 结论 | 原因 |
|---|---|---|
| Agent 原理（LLM 调用、Prompt、状态、记忆、工具、评测） | **必学，全员** | 这是答辩、面试、后续一切版本的地基 |
| LangGraph | **必学（负责人 + A 方向）** | 它是把状态机升级为状态图的行业主流框架；我们的 V0.4 编排升级就走它。先懂我们自己的状态机，再学它，事半功倍 |
| Dify 等低代码平台 | **不学（至多 2 小时竞品体验）** | 它是"用别人的 Agent 平台"，不是"会搭 Agent"；技能不可迁移到本项目，流程也无法走代码评审与版本管理。会拖节点 ≠ 会搭 Agent |
| RAG（embedding/检索） | **必学（B 方向）** | V0.5 课件知识库问答的核心 |
| 模型微调/训练 | **不学（现阶段）** | 没有真实作答数据之前谈训练是空中楼阁；先把数据攒起来 |

## 五个阶段（每阶段都有验收，不验收不算学过）

### 阶段 0 · 工程地基（全员，2 天）
- Git/GitHub：分支、PR、Review、CI 红绿是什么意思
- Python 基础 + JSON + HTTP/API 基本概念
- **验收**：每人独立把项目跑起来、跑通 `pytest`、提交一个能合并的小 PR

### 阶段 1 · LLM 应用基础（全员，2–3 天）
- 大模型 API 的消息结构（system/user/assistant）、temperature、上下文
- Prompt 工程：角色、约束、少样本、结构化输出（让模型回 JSON）
- 对应代码：精读 `app/llm.py`（判读与对话都在这里）
- **验收**：每人亲手写一个脚本，用 DeepSeek 完成一次"开放题判读"并解析返回的 JSON

### 阶段 2 · Agent 架构（全员，3–4 天）
- 状态与状态机：教学流程为什么必须是可解释的状态机，而不是一整个大 Prompt
- 记忆：短期上下文 vs 长期画像（对应 `storage.py` 与 profile）
- 工具调用（function calling）的概念与边界
- 对应代码：精读 `app/tutor.py`，能画出完整状态转移图
- **验收**：每人对着代码讲清"一次作答从前端到数据库的完整路径"，讲不清不过关

### 阶段 3 · LangGraph 编排（负责人 + 1 人，1 周，与 V0.4 并行）
- 官方概念：State、Node、Edge、条件边、持久化（checkpointer）
- 练习：用 LangGraph 把现有单个知识点的教学流程重写一遍，与现有状态机跑同一套
  评测案例对比，结果写进 `docs/`——学框架的唯一正确方式是拿它和已有实现对照
- **验收**：LangGraph 版本通过全部现有测试；写出一页对比结论（何时值得迁移、何时不必）

### 阶段 4 · RAG 与知识工程（B 方向，1 周，与 V0.5 并行）
- 文档切片、embedding、向量检索、引用溯源、查不到就拒答
- 对应任务：把老师课件做成可检索知识库，「问老师」的回答必须带出处页码
- **验收**：20 个课程问题，回答引用出处准确率 ≥ 90%，无出处时能明确说"课件里没找到"

### 阶段 5 · 评测与开源工程（全员参与，持续）
- 教学案例集（Evals）：预设学生回答 → 期望教学动作，改任何教学逻辑都要回归
- 版本与发布：语义化版本、CHANGELOG、Release、Issue/PR 模板
- **验收**：案例集进 CI；每次发版有 Release Notes

## 对全员的硬性要求（最终目标口径）

1. 每人能独立运行、测试、部署（Docker）本项目
2. 每人至少精读并能讲解一个核心模块（tutor / llm / knowledge / storage 之一）
3. 每人至少完成阶段 1、2 的验收；LangGraph 与 RAG 按方向分工完成阶段 3、4
4. 合并门槛：CI 绿 + 一人 Review + 新功能带测试，没有例外
5. 不接受"会在 Dify 里拖节点"作为会搭 Agent 的证明
