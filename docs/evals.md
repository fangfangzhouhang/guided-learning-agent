# 评测 Harness（Eval Harness）

包在教学引擎外面的评测与护栏层。目的：任何改动（提示词、判分、教学规则、
题库）进来之前，先用同一套尺子量一遍——“感觉变好了”不算数，数字说了算。

## 两层结构

### A. 教学案例（确定性，进 CI）
`evals/teaching_cases.json`：脚本化的“学生剧本”回放到真实引擎上
（临时数据库，不碰生产数据），逐案断言教学决策必须是什么：

| 案例 | 剧本 | 期望 |
|---|---|---|
| tc01 | 全程答对、无提示 | mastered |
| tc02 | 全程答错 | needs_review |
| tc03 | 每题先要 2 次提示再答对 | passed_with_help（提示上限 1） |
| tc04 | 引导题连错两次触发薄弱标记、其余全对 | passed_with_help |
| tc05 | 诊断题选带误区码的错误项 | 画像记下该误区 |
| tc06 | 信心 5 分却答错 | 返回 calibration 提醒 |
| tc07 | 独立测验阶段请求提示 | 必须被拒绝 |

由 `tests/test_evals.py` 接进 pytest，CI 每次自动跑，全过才算绿。

### B. 判分一致率（量判分器，不量引擎）
`evals/golden_explanations.json`：人工标注的开放题答案（种子集 12 份，
覆盖完整/残缺/误区反向/凑字数攻击/离题五类），分别让两种判分器打分，
和人工标注比一致率，分歧逐案列出：

- 离线关键词判分（`tutor._judge` 的内置兜底）
- LLM 判分（配了 `LLM_API_KEY` 时自动跑；已按结构化 rubric 提示判分，
  并做自洽投票——默认独立判 3 次多数决，`JUDGE_SAMPLES` 可调）

## 怎么跑

```bash
python -m evals.run_evals        # A + B，报告写 evals/report.json
python -m pytest -q              # 只跑 A（CI 同款）
```

## 基线（2026-11-07，当前版本实测）

- A 教学案例：**7/7 通过**
- B 离线关键词判分一致率：**7/12 = 0.583**——不好看，但这正是 harness 的价值：
  它把离线判分的两类弱点都量了出来
  - **被关键词骗过**（4 例）：因果说反、结论方向错、凑字数灌水，只要关键词
    密度够，关键词判分一律放行
  - **冤枉好答案**（1 例）：全口语化、因果完整的好答案因为没出现词表里的
    原词（“发射极电位”）被判不通过
- 结论：离线判分只能当兜底，正式学习请配 LLM 判分；LLM 判分的一致率
  待配 key 后用同一金标集补测（跑法同上，自动执行）
- B LLM 判分一致率（2026-11-07 补测，rubric 结构化提示 + 3 次自洽投票，
  模型 deepseek-chat）：**11/12 = 0.917**。唯一分歧是 ge09（“方向对但没
  结合公式”的残缺答案）——金标按题目“结合公式说明”的要求标了不通过，
  LLM 判了通过；这条本身是边界案例，金标从严、判分从宽，分歧记录在案，
  后续扩金标时复议。其余探针（因果说反、结论方向错、凑字数灌水）全部
  被正确拦下，口语化好答案也被正确放行——离线判分的两类弱点在 LLM
  判分上均未复现
- **扩容复测（2026-11-07，金标集 12 → 30 份）**：新增变体包括换序叙述、
  极简完整链（“IC↑→VE↑→VBE↓→IB↓”）、编造机制（Re 热敏限流）、只写公式、
  答非所问的正确事实、串并联说反、带数值例证等。结果：LLM 判分
  **29/30 = 0.967**，唯一分歧仍是 ge09——复议结论：题面明确要求结合公式，
  维持人工标注“不通过”，判分从宽记为已知边界分歧；离线判分 17/30 = 0.567，
  与扩容前一致（兜底定位不变）。教学案例同步扩至 8 条（新增 tc08 复习
  队列：学完生成 FSRS 卡片、到期进队列）

## 怎么加案例

- 新的教学行为规则 → 在 `teaching_cases.json` 加一条剧本（先写期望，
  再改引擎，让案例先红后绿）
- 新的开放题 → 给它配至少 5 份金标答案（完整、残缺、误区各一，
  外加一份口语化好答案、一份凑字数灌水），目标总量 30–50 份
- 金标的标注人不能是写这道题的人（贡献规则：双人核对）
